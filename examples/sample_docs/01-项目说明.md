# LocalDocQA 项目说明

## 一、这个项目解决什么问题

写论文、做课程实验时，资料往往散落在几十个 PDF、Word 和 Markdown 文件里。直接把这些文件
上传到在线 AI 工具，等于把未公开的实验数据、内部文档交给第三方服务；而自己翻文件又非常低效。

LocalDocQA 的做法是：把文档切分、向量化后存到本机的一个目录里，提问时先在本机检索最相关的
若干段，再交给同样跑在本机的模型归纳成回答，并在每句结论后面标注来源编号。整个过程只有本机
的磁盘和本机模型进程参与，不需要联网，也不会上传任何文件内容。

## 二、三条硬性要求

1. 隐私优先：文档、向量、对话记录一律保存在本地 data 目录，任何环节都不调用云端 API。
2. 可溯源：回答里出现的 [1]、[2] 必须能对应到具体的文件名、页码和原文片段，不允许"编来源"。
3. 可降级：没有安装大模型时，工具仍然能用——退化为"原文摘录"模式，先保证检索这一环可用。

## 三、技术选型说明

- 切分：自研递归切分器，分隔符表把中文句号、问号、分号放在靠前位置，避免把一句话切成两半。
- 向量化：默认调用 Ollama 的 nomic-embed-text（768 维）；断网或未安装时自动回退到离线哈希向量。
- 向量库：用 numpy 矩阵加余弦相似度自建，一个集合一个目录，只有三个文件，出问题能直接打开看。
- 生成：默认 Ollama 的 qwen2.5:7b；也可以接任何 OpenAI 兼容网关，例如 vLLM 或 LM Studio。
- 界面：Streamlit 单文件应用，够用、改起来快，不追求前后端分离。

## 四、使用流程

1. 安装 Ollama，执行 ollama pull qwen2.5:7b 和 ollama pull nomic-embed-text。
2. 安装 Python 依赖，执行 streamlit run app.py 打开网页界面。
3. 在左侧新建集合（例如"毕业论文"），上传 PDF 或 Word 文件，等待入库完成。
4. 在对话框提问，回答下方会列出本次使用的来源片段和相似度分数。
5. 如果某个文档更新了，在"文档"页删除旧版本，再重新上传即可。

## 五、已知限制

- 扫描版 PDF 没有文字层，当前版本不做 OCR，会提示"未提取到文本"。
- 单个集合建议控制在两千个文档以内，再大建议换成 FAISS 索引。
- 检索是纯向量召回，没有做关键词混合检索，专业术语缩写较多的场景召回率会下降。
- 回答质量依赖模型本身，7B 模型在长文档多跳推理上仍然容易漏掉中间步骤。
