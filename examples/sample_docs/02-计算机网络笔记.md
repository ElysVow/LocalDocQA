# 计算机网络课程笔记（节选）

## TCP 三次握手

客户端先发送 SYN 报文，携带自己的初始序号 seq=x，进入 SYN-SENT 状态。
服务器收到后回复 SYN+ACK 报文，确认号 ack=x+1，同时携带自己的初始序号 seq=y，进入 SYN-RCVD 状态。
客户端再发送 ACK 报文，确认号 ack=y+1，双方进入 ESTABLISHED 状态，连接建立完成。

三次握手的本质是让双方都确认"对方能发、对方能收"，同时交换初始序号。
如果只有两次握手，服务端无法确认客户端是否收到了自己的 SYN，历史上残留的连接请求
会造成服务端资源被无效占用。

## TCP 四次挥手

主动关闭方发送 FIN 报文，进入 FIN-WAIT-1 状态；被动关闭方回复 ACK，进入 CLOSE-WAIT 状态，
此时连接处于半关闭，被动方仍可以继续发送数据。被动方数据发完后发送自己的 FIN，
主动方回复 ACK 并进入 TIME-WAIT 状态，等待 2MSL 后连接彻底释放。

TIME-WAIT 等待 2MSL 的作用有两个：一是保证最后一个 ACK 能到达对方，
二是让本次连接产生的旧报文在网络中自然消亡，避免干扰后续使用相同四元组的新连接。

## 拥塞控制

慢开始阶段拥塞窗口从 1 个 MSS 开始，每经过一个 RTT 翻倍，直到达到慢开始门限 ssthresh。
进入拥塞避免阶段后，每个 RTT 窗口只加 1 个 MSS。出现超时重传时，ssthresh 降为当前窗口的一半，
窗口重置为 1 并重新慢开始；如果收到三个重复 ACK，则执行快重传与快恢复，窗口降为一半后继续线性增长。

## 常见端口

HTTP 默认使用 80 端口，HTTPS 使用 443 端口，SSH 使用 22 端口，DNS 使用 53 端口。
实验环境中常用 8080 作为本地 Web 服务的替代端口，避免与系统服务冲突。
